Preserve static WithAPIKey, WithAPIKeyFunc, environment fallback, existing API-key endpoint behavior and mutual-exclusion validation. Never recognize auth mode by a token substring.

Add provider-owned `anthropic.NewLoginFlow(opts ...LoginOption) (llm.LoginFlow, error)` with explicit browser/copy-code login mode, HTTP client and timeout options as needed. Browser default; headless copy-code matches Pi's separate registered redirect. Endpoint overrides remain private test seams. No public generic token-source callback, no new core credential union and no user credentials in application DTOs.

Existing AuthCredential Type/Access/Refresh/Expires metadata suffices for this fixed-client Pi grant. Missing ClientID is valid for these Pi credentials and uses the documented-in-code pinned public client constant; it does not fabricate a newly issued registration. New login can leave ClientID empty to preserve Pi's file shape. ## Pinned Pi login/refresh wire contract

- Authorize `https://claude.ai/oauth/authorize`; exchange/refresh JSON POST `https://platform.claude.com/v1/oauth/token`, Accept and Content-Type application/json.
- Public fixed client ID `9d1c250a-e61b-44d9-88ed-5944d1962f5e` (Pi stores base64 source text). This is public client metadata, not a secret.
- Scope: `org:create_api_key user:profile user:inference user:sessions:claude_code user:mcp_servers user:file_upload`.
- Browser listener on IPv4 loopback, preferred port 53692 then ephemeral fallback, callback `/callback`, redirect `http://localhost:<port>/callback`. If no loopback listener can bind, fail with an actionable local-listener error; this implementation deliberately retains the existing private local launch handoff.
- Copy-code mode redirect `https://platform.claude.com/oauth/code/callback`, manual returned code#state.
- Authorization query: code=true, client_id, response_type=code, redirect_uri, scope, S256 code_challenge/code_challenge_method, state. Pi uses the verifier as state. Preserve this provider-specific behavior without changing OpenAI's independent-state flow.
- Exchange JSON: grant_type=authorization_code, client_id, code, state, redirect_uri, code_verifier. Refresh: grant_type=refresh_token, client_id, refresh_token.
- Parse successful access_token, refresh_token, positive finite bounded expires_in; optional scope. Store Expires exactly as Pi: now + expires_in minus five minutes. Treat imported Pi Expires as already adjusted. Add an explicit internal resolver policy selecting zero additional margin (for example a RefreshBeforeSet flag alongside RefreshBefore); current zero-without-policy retains its existing five-minute default for OpenAI. Anthropic sets the explicit zero policy. Refresh when now >= adjusted Expires, never subtract a second margin; validate arithmetic/overflow and test equality boundaries and short-lived grants.
- Reject redirected token responses, bound payloads/timeouts and normalize errors. Do not copy Pi's raw response-body diagnostics.

`provideroauth.LoopbackFlow` currently rejects port 0 and returns the configured port instead of actual listener port; browser fallback needs a small internal engine amendment and OpenAI regression coverage. It also fixes independent state and a loopback redirect and accepts only complete callback URL/query, while Pi permits code#state and code-only. Prefer a narrowly generalized internal flow config or an Anthropic-owned implementation sharing helpers; do not weaken OpenAI callback validation. Manual parser must compare supplied state in constant time and use flow-owned state for code-only input just as Pi does. Bound every field, one submit/complete, reject conflicting/duplicate input and release resources on cancellation.

Existing public LoginAuthorization requires a non-secret loopback launch target. Product decision: retain that contract and do not create a new remote browser handoff project. Even copy-code mode serves an ephemeral loopback launch redirect while authorization redirect_uri remains the cloud code page. A browser on another machine must have an explicitly configured SSH/container port forward reaching the actual selected launch port; an unforwarded remote browser cannot launch this login. Copy-code mode does not remove that launch requirement. If all listener ports are unavailable, fail with a safe actionable local-listener error rather than expose provider state in DTOs. Document this limitation in login instructions/tests and public docs: local browser and forwarded remote browser are supported; full Pi remote-browser/listener-unavailable parity is not claimed. Authorization codes, state and provider authorization URLs remain outside browser argv, history, logs and ordinary application DTOs.

## Pinned Pi inference contract and adaptation boundary

OAuth headers: bearer Authorization, no X-Api-Key; Accept application/json; anthropic-version supplied as 2023-06-01 by SDK; anthropic-dangerous-direct-browser-access=true; User-Agent=claude-cli/2.1.280; x-app=cli. Beta features include claude-code-20250219 and oauth-2025-04-20 plus existing relevant request betas, deduplicated. Preserve explicit beta override semantics where the current API exposes them; do not drop mandatory existing positional/tool feature headers accidentally.

OAuth request-only system preamble matches Pi: `You are Claude Code, Anthropic's official CLI for Claude.` Existing user system content follows in its current order, with cache controls preserved as appropriate. Do not mutate the caller's llm.Request, durable history, visible product identity or console marketing. The response/tool adapter owns compatibility normalization, not application code.

Canonical tool mapping (case-insensitive): Read, Write, Edit, Bash, Grep, Glob, AskUserQuestion, EnterPlanMode, ExitPlanMode, KillShell, NotebookEdit, Skill, Task, TaskOutput, TodoWrite, WebFetch, WebSearch. Unmatched names remain unchanged. Apply to declared tools, replayed tool-use blocks, references and forced tool selection where applicable. Map returned tool names in blocking/streaming results back to the original request tool names using an immutable map owned by that single operation; never store a current reverse map on the shared Provider. Keep IDs and arguments unchanged. Concurrent requests with different original casing must not affect each other. Reject ambiguous case-folded collisions before network rather than route a tool call unpredictably. Ensure internal structured-output tools remain internally identified and replay-safe.

Auth mode affects request construction, so resolving only in HTTP middleware is insufficient. Resolve typed credential/auth mode at operation entry and build params plus per-request tool reverse mapping for that mode. Carry an unexported prepared-operation context marker/source into the SDK call. Before each actual dispatch (initial attempt, SDK continuation/transport retry and the sole auth retry), explicitly Read the same exact owned store again, validate its current mode and fixed ClientID, and check request context cancellation. A stale unexpired `Resolver.WithStored` value is not ownership proof: it skips the store reread. The operation source must perform that verification itself and may use only the current owned credential. Reject ownership loss, deletion or API-key/OAuth mode changes before dispatch; do not restart with ambient credentials or send previously transformed params under a new mode. Same-mode owned refresh may advance the revision and is persisted before use. This is a pre-dispatch verification boundary, not a claim that remote logout can retract bytes already sent.

`Provider.Client()` exposes the raw SDK and must remain API-key compatible. For stored OAuth, its middleware rejects any raw SDK request lacking this provider's unexported prepared-operation marker/source with sanitized ErrUnsupported before network or refresh. A marker from a different provider instance is invalid. The normal Chat/ChatStream/Models/CountTokens methods supply their own marker after preparation. Raw SDK users must call these public prepared provider operations for OAuth; no newly exported unsafe bypass is added. Test raw Messages/stream/count/models requests fail closed for OAuth and existing API-key raw SDK requests continue working. A raw call while a stored entry changes from API key to OAuth must also fail closed, not acquire an OAuth token implicitly.

Never hold application locks while rendering. After a detached refresh completes and persists, check the initiating request context again before inference/retry. Cancellation returns the canonical context error and leaves the stored rotation intact.

Models and CountTokens must use the same typed header path; test them explicitly. Pi relies heavily on its local catalog, so OAuth support for live models/count endpoints is not established by the Pi Messages implementation. A rejected discovery endpoint cannot be worked around by claiming unverified account models are available; return accurate capability/discovery failures and preserve the user's old active profile.

## Exact ownership, refresh, revocation, retry and cancellation

1. Initial login has no store access. It returns a credential only; console owns staging and exact-profile publication. Cancel is idempotent, closes the listener and pending exchange, and clears ephemeral secrets. State/PKCE/errors never reach DTOs or terminal history. Preserve the existing boundary that a successful exchange racing caller cancellation can return minted material to the owned staging/cleanup path.
2. Reuse `provideroauth.Resolver` for locked rotation: optimistic Read, authoritative reread inside CredentialStore.Modify, refresh once per current credential revision. It preserves renewed tokens before use and checks changed credentials after 401. Its unexpired WithStored path does not reread authority: the Anthropic operation source independently checks the owned store before every dispatch/retry as specified above.
3. Wait for store exclusivity obeys caller cancellation. Once token rotation begins, use the existing detached bounded refresh context (15 seconds default); persist a successful rotation even when the initiating request was canceled. Return the caller's canceled operation without issuing inference after cancellation; a future request can use the safely persisted token.
4. Console must pass `RecordOwner.CredentialStore("anthropic")`, not a generic authstore opened at user paths and not the existing hardcoded `"openai"` mapping. Its owner revision tracks refresh writes; replacement/logout invalidates old owner. Concurrent changes never fall through to ambient credentials or overwrite new owners.
5. Apply bearer headers only to OAuth requests; explicitly clear X-Api-Key. API-key path explicitly clears OAuth-only Authorization/beta/identity state so header mutations cannot bleed across sequential credential changes. HTTP requests must be cloned before auth/header mutation. Apply the explicitly requested pinned Pi compatibility headers and request-only system/tool transforms; preserve caller-owned request data and return original tool names.
6. One forced-refresh-and-retry after an initial HTTP 401 may reuse `provideroauth.DoWithAuthRetry` only after replacing its unlimited 401-body drain with immediate close without reading. The default streaming client has no total timeout, so even byte-capped draining can hang on a stalled response; sacrifice connection reuse and never log the body; never retry a stream after events or ambiguous network delivery. A second 401 is terminal. Do not force refresh on 403 or try additional identities after a rejection. Existing 429/503/529 retry policy remains opt-in.
7. Refresh revocation/invalid_grant returns ErrAuth; no secret/body/error-description echo, no silent deletion, no environment fallback. Leave replacement/relogin to explicit user flow. Local logout deletes only the exact owned record and retires the provider; do not claim remote grant revocation without a documented endpoint.
8. Token HTTP responses are size bounded; validate JSON, required tokens, bounded positive expiry, optional scope if the final protocol requires it, status mapping and cancellation. Reject redirects on token endpoints. Use existing safe error helpers; custom client errors may contain tokens and must be normalized. Classify errors with errors.Is for context.Canceled/context.DeadlineExceeded (including wrapped transport errors) and return the canonical context error or sanitized typed timeout; never wrap or return the original credential-bearing transport string. Apply this to token exchange, refresh, inference and listener failures.
9. Persistence error means no minted token can be used for inference. The record owner classifies committed versus indeterminate writes; preserve that behavior. Store Modify, not a callback after an unlocked refresh, is authority.
10. Custom API base URLs: safest initial OAuth contract accepts only the documented Anthropic origin; return ErrUnsupported for incompatible override before reading/sending a bearer. Synthetic endpoint substitution remains private transport seam. API-key custom endpoint behavior is unchanged. Disable credential-bearing redirects unless the pinned protocol requires an explicitly allowed same-origin redirect.
